# Design System: IWAC Theme

## Overview

**Creative North Star: "The Research Broadsheet"**

A 20th-century broadsheet operated as a scientific instrument. The site is a scholarly
database — LLM sentiment models, LDA topics, embeddings, IIIF — that carries the visual
grammar of the newspapers it preserves: masthead wordmark, uppercase section strip,
thick 2px ink rules, datelines, ledger-style result rows, a duotone press-collage hero.
The execution is a modern broadsheet's digital archive run by a university press:
newspaper typographic conventions with Linear/Stripe-grade product polish.

Density is a feature, not a compromise: researchers want more items per screen, flat
ledger rows over boxed cards, metadata flowing inline with interpunct separators.
Restraint is the resting state — the quiet control is the default and loudness opts in.
Confirmed anti-references: not a small museum's website, not a warm editorial magazine,
not a generic dashboard; no cream or parchment, no pastiche of aged paper.

The system is enforced, not merely written down. Every value the token generator
publishes is compared by a guard in this repo and in both consumer modules; a rule that
lives only in prose is a rule that has already drifted. That doctrine — publish it and
assert it — is why the palette below includes the twenty categorical chart slots and the
nine resource-type hues that once lived as loose hex in a sibling repo.

**Key Characteristics:**
- Newspaper grammar (rules, datelines, ledgers) executed with product-grade polish
- Density over comfort; typography as architecture, rules as joinery
- Near-white cool-neutral light mode; warm "lamplit reading room" dark mode
- One brand accent used sparingly; category encoded as dots, never fills
- Two themes declared in full — dark is a redeclaration, never an inherited substitution
- AI-generated content visibly marked (computational honesty)

## Colors

An OKLCH-derived palette: near-white warm-tinted surfaces, cool-neutral inks, one
burnt-orange accent, and two encoding scales (resource type, chart series), all cascading
from admin-overridable seeds via `color-mix(in oklab, …)`.

### Primary
- **IWAC Burnt Orange** (#ce4115): the sole UI accent, derived from seed `#e64a19`
  darkened 8% in light mode. Appears as focus states, current/active states (nav tab,
  active filter chips), dateline interpuncts, categorical dots, key counts, and the
  duotone hero plate — never as heading text, per-row badge fills, or decorative wash.
  Hover deepens to #b03710, active to #942c0c.

### Secondary
- **Slate** (#394f68): **data-only** — chart series slot 2 and corpus comparison in
  IwacVisualizations, plus the `publication` resource-type dot. Never buttons, links,
  focus, or any UI chrome.

### Neutral
- **Ink Strong** (#05070c): masthead rules, headings, strongest emphasis.
- **Ink** (#13161c): body text.
- **Ink Light / Ink Subtle / Muted** (#3f4349 / #5a5e63 / #66696e): secondary text,
  uppercase metadata labels, quiet chrome.
- **Ink On Pastel** (#0d121b): the one text ink used on the tinted status grounds, so a
  notice never relies on the body ink landing legibly on a colored plate.
- **Surface / Raised / Sunken / Background** (#fdfcfb / #faf8f6 / #f4f1ef / #f7f5f3):
  near-white at chroma ~0.002 — an imperceptible warm tint, never cream.
- **Border Light / Border / Border Strong** (#e2e5e8 / #ced1d6 / #aeb1b7): hairlines
  divide rows; the 2px ink rule (not a border token) opens sections.

### Status and its tints
Success / warning / error / info (#2e9052 / #d66800 / #c9222b / #037ac0) carry notices
and double as the fixed categorical map for resource types and entities (dots on
outlined chips, `--type-*`). Because each status hue is *also* a dot, it is
calibrated as a non-text mark: `--warning` sits at `oklch(63.5% 0.18 60)` — down
from 66% in 2.14 — so the document and organisations dots clear 3:1 on all four
light surfaces (3.51 / 3.40 / 3.31 / 3.20) instead of clearing on the two
lightest and failing on the other two. Chroma holds at 0.18, keeping the amber
identity and the ~16° of hue separation from `--primary` that keeps the article
and document dots apart in one list. Dark is unchanged. Each has a paired ground: in light mode a flat pastel at
`oklch(96% …)` on the status hue; in dark mode a 22% `in oklab` mix of a **darker,
more saturated base than the foreground hue** — `oklch(50% 0.13 152)` success,
`oklch(55% 0.16 60)` warning, `oklch(50% 0.18 25)` error, `oklch(50% 0.14 245)` info.
Those four bases are deliberate: mixing the light-mode status hue into a lamplit ground
produced a washed, hue-shifted plate, so the dark tints are struck from their own
lower-lightness bases and resolve to `rgba(178,84,0,0.22)` and `rgba(179,34,40,0.22)`
for warning and error. They are part of the shipped palette, not a stray.

### Encoding scales
- **Resource type / entity** (`--type-article` … `--type-entity-organisations`, 9
  tokens): a fixed semantic map, rendered as dots. Declared in **both** theme blocks —
  as `:root`-only aliases they inherited already-substituted light hues under the
  `data-theme` toggle, and the publication dot measured 2.41:1 on the dark ground.
- **Categorical series** (`--series-1` … `--series-20`): the theme-owned chart palette.
  Slots 1 and 2 alias `--primary` and `--secondary` and therefore flip with the theme;
  slots 3–20 are literals held at parity across light and dark for now. Slots 4
  (#bb4c49) and 8 (#876c45) were lifted out of the crossover band so knocked-out labels
  stay legible on them.

The dark palette is not a mechanical inversion: surfaces go warm (oklch hue ~70–80,
chroma ~0.012 — the "lamplit reading room"), primary lightens to #ec653f, and every
composed token that references a palette entry — the three focus tokens, the glows, the
selection wash, the panel set — is **redeclared** in the dark block so it composes
against dark referents. Dark values live in `tokens.json` and the sidecar.

### Named Rules
**The One Plate Rule.** The duotone hero — a grayscale collage multiplied over a primary
ground — is the one big color statement on the site. Everything else earns primary only
as an accent.

**The Dot-Not-Fill Rule.** Category is a dot on an outlined chip, never a filled or
pastel badge. Ten filled badges per screen is shouting; ten dots is an index.

**The Accent-Not-Text Rule.** `--primary` is an accent, never running body text.
As text it measures 4.67 / 4.51 / 4.40 / 4.25:1 on surface / raised / background /
sunken — it clears AA on the two lightest surfaces and misses on the other two, so
the same declaration passes or fails depending on which panel it lands in, and a
component does not know that. Sanctioned: links, controls and their states,
current/active state, large display text (the 404 numeral, KPI figures),
pseudo-element marks (interpuncts, `::marker`, chevrons, dots), and every non-text
use — borders, fills, focus rings, the duotone plate. Not sanctioned: paragraph,
list-item or table-cell copy, ledes, abstracts, anything set from
`--font-serif-text`. Darkening the token is not the fix — the brand seed is
admin-configurable, so no fixed value can guarantee 4.5:1 for a site that sets its
own; scoping the use is the durable answer.

**The Data-Only Secondary Rule.** #394f68 exists for data. If it appears on a button,
link, or focus ring, it is a bug.

**The Mirror-Both-Blocks Rule.** A custom property is substituted at computed-value
time on the element that *declares* it, so a token whose value contains `var(…)`
must be declared in **both** theme blocks, and the rule runs both directions. A
light-only composition is substituted against light referents and inherited frozen
by every dark descendant — a whole-theme failure that looks like nothing until a
contrast probe finds it. A dark-only declaration is worse-hidden still: with no
light counterpart, `body[data-theme="light"]` cannot win back on a dark-OS machine
and a manual light choice keeps the dark value. Since 2.14 the light and dark token
blocks are a **mixin pair** carrying the same names — the shadow set, the panel set,
the glows and the three composed focus tokens are declared twice, by construction.

**The Published Scale Rule.** A color that encodes data belongs in `tokens.json` with a
name, a light value and a dark value. Owning a scale means deciding it, never leaving it
unpublished in a consumer's source.

## Typography

**Display Font:** Besley (with Source Serif 4, Georgia fallback)
**Body Font:** Public Sans (system-ui fallback)
**Long-form Font:** Source Serif 4 (Georgia fallback)

**Character:** a Clarendon slab masthead over a rational sans — the newspaper's voice
and the instrument's legibility. All three faces are verified against the
Arabic-transliteration diacritics `ḥ ṣ ḍ ṭ ẓ ʿ ā ī ū`.

### Hierarchy
The ramp is ten steps (0.6875 / 0.8125 / 0.9375 / 1.0625 / 1.1875 / 1.5 / 1.875rem, then
three clamps), fluid only at the top three. Headings step **up** one token at ≥768px, so
each display role names two sizes.

- **Display** (800, clamp 3.25–4.75rem): masthead wordmark and homepage hero only.
- **Headline** (600, clamp 2.75–3.75rem, 1.08): page titles (`h1`), opened by a 2px ink
  rule; sits at the 2.25–3rem clamp below 768px.
- **Subhead** (600, clamp 2.25–3rem): section headings (`h2`); 1.875rem below 768px.
  Never painted in primary — coloring every `h2` floods an article-length page.
- **Title** (600, 1.5rem): `h3` and item titles in ledger rows; 1.875rem at ≥768px.
  Block section heads that sit *inside* a record (citation panel, linked resources) drop
  to 1.1875rem at weight 700 so they name their section without shouting over it.
- **Body** (400, 1.0625rem, 1.5): UI prose in Public Sans.
- **Body-serif** (400, 1.0625rem, 1.7): article full text, ledes, long-form reading, at
  measures 44–52.5rem; long AI and OCR prose runs one step up at 1.1875rem.
- **Label** (600, 0.8125rem, +0.04em, UPPERCASE): datelines, metadata labels, chips,
  disclosure toggles, the nav strip; drops to 0.6875rem (`--text-2xs`, the absolute
  floor) for the densest eyebrows. Wider tracking (+0.08em) exists for the most spaced
  settings.

### Named Rules
**The Slab Tracking Rule.** Besley display sizes track at -0.01em, never the full
-0.02em — slab serifs clog at tight tracking.

**The Lining Zero Rule.** Besley's `tnum` zero is broken (frozen at 55 units across
weights); use `font-feature-settings: "lnum"` for aligned numerals, never
`tabular-nums` with the display serif. All headings set `"kern" "liga" "dlig" "lnum"`.

**The No-14px Rule.** The type scale deliberately skips 14px; 11px (`--text-2xs`) is
the floor. Absolute `font-size` literals fail `npm run check:tokens` — use `--text-*`
tokens. The check reads the whole value, not just its first token, so `clamp()`,
`min()` and `max()` are not an escape hatch: a fluid size composes `--text-*` steps
(or `calc()` on them), and the error page's watermark numeral and the block-group
heading were moved onto the scale in 2.14 for exactly that reason.

**The Bound Punctuation Rule.** French sets a space before `: ; ! ?` and `»` and after
`«`. Rendered as an ordinary space it is a legal line-break opportunity, and a headline
can open a line with an orphaned colon that reads as a bullet. Titles pass through the
`FrenchSpacing` helper, which rewrites those spaces to U+202F NARROW NO-BREAK SPACE —
same gap, no break.

## Layout

Content column capped at 1300px (`--content-max-width`); reading measures at 44rem
(narrow, article text), 52.5rem (base), and 72.5rem (wide). Spacing runs a 4px-based
scale (0.25–10rem) with semantic aliases (xs–3xl). The sidebar, where used, holds 27%.
The sticky masthead is 133px tall (160px at ≥1024px): wordmark row plus uppercase nav
strip, closed by a 2px ink rule; below 1024px a drawer with a slim ink hamburger takes
over, and below 600px the wordmark swaps to the per-site acronym (full title stays as
the accessible name).

Breakpoints are a published contract (`tokens.json`): xs 400, sm 600, md 768, lg 1024,
xl 1200, xxl 1460px. `min-width` sits **on** a published breakpoint and `max-width` at
**breakpoint − 1px** — one spelling, not two: Bootstrap's `− 0.02px` was tolerated
until 2.14 and the theme carried both idioms in files that reflow the same header.
Neither is wrong alone; carrying both is. Guards in this repo and in both consumer
modules now assert it. `@container` queries are exempt — they measure their
container, not the viewport.

Density rules the page grammar: result lists are flat ledger rows separated by
hairlines, never boxed cards; multi-value metadata flows inline with primary
interpuncts; resource metadata sits in a 168px-label two-column ledger with hairline
row separators, selected with `> dl > .property > dd` so a nested annotation `<dl>`
never inherits the label column.

A long body — a full OCR transcript — is not allowed to own the page: past a length
threshold it is cut to an opening extract with the remainder behind a native
`<details>`, so the sections below it stay reachable.

### Named Rules
**The Separator-Ends-The-Line Rule.** An inline separator between repeated values is
drawn with `::after` on the preceding value, never `::before` on the following one. Each
value is an atomic wrap unit, so a leading separator opens whichever line its box starts
— an interpunct that reads as a bullet.

## Elevation & Depth

Flat by conviction, layered by exception. Hierarchy comes from rules and typography;
shadows are reserved for true panels (charts, dropdowns, the sentiment scales) and the
opt-in primary button glow. Rows, tags, chips, filter bars, and the AI lede never cast
shadows — they are drawn with rules. `backdrop-filter` glass exists in exactly one place:
the sticky header (`--surface-overlay`, rgba(253,252,251,0.94) light,
rgba(17,12,8,0.95) dark); opaque popovers use `--surface`.

Dark mode does not reuse the light shadow set: its ambient shadows are struck from pure
black at higher alpha and greater spread (`--shadow-lg` becomes
`0 12px 28px -8px rgba(0,0,0,0.35), 0 8px 16px -8px rgba(0,0,0,0.2)`), because a
neutral-ink shadow is invisible on a lamplit ground. The whole depth vocabulary —
shadows, shadow colors, the panel set, the glows, the three composed focus tokens —
is declared in each theme block rather than composed once and left to inherit.

### Shadow Vocabulary
- **shadow-xs → shadow-lg** (`0 1px 2px 0 rgba(20,22,27,0.06)` up to
  `0 10px 15px -3px rgba(9,11,15,0.12), 0 4px 6px -4px rgba(20,22,27,0.06)`): neutral,
  panel-only ambient depth.
- **panel-shadow** (= shadow-sm): the default panel treatment, paired with
  `--panel-bg`, `--panel-border` and `--panel-radius`.
- **glow-xs / glow-sm / glow-md** (primary-tinted, e.g. `0 2px 6px -1px
  rgba(206,65,21,0.25)`): reserved for the filled-primary control's active / rest /
  hover states.
- **focus-outline** (`2px solid var(--focus-color)`): the default focus indicator.
- **ring-focus / ring-focus-sm** (`0 0 0 3px rgba(206,65,21,0.3)` / `0 0 0 2px` at 22%):
  the box-shadow focus ring, for controls whose outline would be clipped by an
  overflow ancestor or whose shape the outline can't follow.

### Named Rules
**The Glass Once Rule.** Backdrop-filter belongs to the sticky header and nowhere else.

**The Rules-Not-Boxes Rule.** Before adding a shadowed card, try a 2px ink rule or a
hairline. Boxes are a last resort for true panels. The AI lede, the linked-resources
filter bar, and the transcript disclosure were all boxes once and are all rules now.

**The Outline-First Focus Rule.** `--focus-outline` at 2px offset is the focus
indicator. The `--ring-focus` halo is the exception for clipped or oddly-shaped
controls, never the default — it is the weaker indicator, and reaching for it by habit
is how a surface ends up with no visible focus at all.

## Shapes

Rectilinear and editorial. Text controls and panels take modest radii (0.375 / 0.5 /
0.75rem); pills (`9999px`) are reserved for uppercase tag chips and circular icon
controls. No blobs, no organic masks, no skewed sections. The recurring silhouette is
the horizontal rule: 2px ink to open (`h1`, section blocks, footer top, KPI figures) and
to close the header, hairlines to divide and to carry "continued" labels. Accent lines
come in 2px (`--accent-line-sm`) and 3px (`--accent-line-md`). Colored side-stripes
(`border-left` accents) are banned — use dots, full-width rules, or nothing.

## Components

### Buttons
The register's signature inversion: **the default is quiet; the loud one opts in.**
- **Base `<button>`:** transparent, 1px `--border` outline, ink text, radius 0.5rem,
  padding 0.5rem 1.5rem, 0.9375rem at weight 500; hover fills `--surface-sunken` and
  strengthens the border. No shadow, no lift.
- **Primary (`.btn--primary` or any submit control):** primary fill, white text,
  `--glow-sm` halo; hover lifts -1px with `--glow-md`; active returns flat on
  `--primary-active` with `--glow-xs`.
- **Secondary (`.btn--secondary`):** outlined in primary, transparent fill; hover
  washes with `--selection-bg` (rgba(206,65,21,0.14)).
- **Icon buttons:** borderless primary glyphs sized off the control scale
  (1.75–3rem); a `::after` overlay extends hit areas to 44px.
- **Focus (all):** `--focus-outline` — 2px primary outline, offset 2px.

### Chips / Tags
Uppercase outlined pills: transparent fill, 1px `--border-strong` outline, full radius,
0.8125rem at weight 600, +0.04em tracking, `--ink-light` text. Resource-type and entity
chips add a categorical dot from the fixed `--type-*` map. Active/selected = primary
border + `--selection-bg` wash, never a filled orange.

### Inputs / Fields
Full-width on `--surface` (panel bg), 1px `--border`, radius 0.5rem, padding
0.5rem 1rem, 1.0625rem. Focus swaps the border to primary and adds the 3px
`--ring-focus` (rgba(206,65,21,0.3)) — no transform. Placeholder in `--muted`.
Checkboxes/radios are custom-drawn with 2px borders.

### Navigation
Masthead: Besley 800 wordmark row, then an uppercase Public Sans strip; the active
section gets a 2px primary tab sitting on the closing ink rule. The mobile drawer
speaks the same register — solid `--surface`, uppercase entries on hairline rules — no
glass, no pill buttons.

### Dateline (signature)
`TYPE · PUBLISHER · DATE` in tracked uppercase label type with primary interpuncts —
the recurring identity device on items, ledger rows, and cards. Its right edge is the
page's utility slot: a quiet **CITE** jump (quote mark, hairline underline) inherits the
row's case, tracking and size and links to the citation panel's stable `#how-to-cite`
anchor. It ships hidden and is revealed only where that panel is actually in the
admin-configured stack.

### Ledger Row (signature)
The result-list unit: hairline-ruled `<li>`, dateline eyebrow, Besley title, 2-line
snippet, quiet interpunct source line, outlined type chip with categorical dot. No
boxes, no shadows, no hover lift. Linked resources on a record speak the same grammar —
opened by a 2px ink rule, filtered by a hairline-underlined control bar, not a table in
a card.

### KPI / Almanac Figure (signature)
2px ink rule on top, uppercase eyebrow, Besley numeral with `"lnum"`; the featured
figure's rule turns primary. No card boxes, no gradients.

### Disclosure / "Continued" Rule (signature)
Progressive disclosure for over-long bodies, built on a native `<details>`: the summary
is drawn as a press "continued" line — a hairline across the reading measure carrying a
tracked uppercase label and a chevron mask that rotates on open. Never a button box; the
UA marker is suppressed, the label swaps by `display: none` so only one wording reaches
the accessible name, and the whole line takes the standard focus ring.

### Pagination & Breadcrumbs
Pagination sits between hairline top/bottom borders, quiet controls, no primary tint at
rest. Breadcrumbs are a plain uppercase crumb line in `--text-xs` at +0.04em — muted
links, primary on hover, current page marked with a primary dot. No chip boxes, and no
truncation: a crumb carrying a resource title wraps rather than becoming an unshrinkable
flex item that pushes the document sideways on a phone.

## Do's and Don'ts

### Do:
- **Do** open sections with 2px ink rules and divide rows with hairlines — typography
  is the architecture, rules are the joinery.
- **Do** declare every composed or aliased token in **both** theme blocks — dark pages
  must compose against dark referents, and a manual light choice on a dark OS must be
  able to win back.
- **Do** publish any color that encodes data as a named light/dark pair in
  `tokens.json`, and let the guards compare it.
- **Do** keep transitions 150–300ms on `cubic-bezier(0.25, 1, 0.5, 1)`; real objects
  decelerate smoothly.
- **Do** mark AI-generated fields with the EU "AI GENERATED" provenance treatment on
  the label, and open the lede on an ink rule.
- **Do** mix colors `in oklab`, derive primary variants from the seed, and run
  `npm run check:tokens` before trusting any token name.
- **Do** test any new font against `ḥ ṣ ḍ ṭ ẓ ʿ ā ī ū` before adopting it.
- **Do** give every interactive element a visible focus state — `--focus-outline`
  first — and respect `prefers-reduced-motion`.

### Don't:
- **Don't** use warm cream or parchment surfaces — wrong register ("manuscript museum
  brochure").
- **Don't** add atmospheric gradients, gradient bars, glassmorphism (outside the sticky
  header), or colored side-stripes.
- **Don't** fill category badges, color `h2`s, or set running prose in primary —
  category is a dot, primary is an accent (4.25:1 on sunken as text).
- **Don't** use cold blue-gray dark surfaces — dark mode is warm ("lamplit"), hue
  ~70–80.
- **Don't** box result rows, filter bars, linked-resource lists, or the AI lede into
  cards.
- **Don't** replace an outline focus indicator with the `--ring-focus` halo for
  convenience, and never with `outline: none` alone.
- **Don't** use bouncing/elastic easing or hover-triggered hero animations (the
  one-time Ken Burns settle is the sanctioned exception).
- **Don't** pair Besley with `tabular-nums` (broken tnum zero) or track it tighter than
  -0.01em.
- **Don't** write an absolute `font-size` literal, inside `clamp()` included, or spell
  the "below" half of a breakpoint pair any way but breakpoint − 1px.
